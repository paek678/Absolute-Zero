## 최신 확정 및 진행 가능 범위 — 2026-09-30

- Q1 핫팩: 현재 구현을 유지한다. 현재 `HotPack.asset`의 기준은 **7초 안에 15회**이며, 이 확인으로 수치를 변경하지 않는다.
- Q10 상대 미니게임: 상대에게 진행 중이라는 표시를 제공하지 않는다. 자기 미니게임 화면과 기존 준비 완료 표시는 유지한다.
- CU2 옷장: 별도 기획 시안을 기다리지 않고 Codex가 사용하기 편한 UI·UX를 설계한다. 기존 5부위·그림 교체·착용/해제·저장·멀티 외형 적용 범위 안에서 화면 배치와 조작을 구체화한다. 현재 모자와 임시 아이콘으로 기능을 만들 수 있으며 최종 그림은 추후 교체한다.
- 다음 개발 순서는 R10 → R11 → R12 → R13 통과 후 C01~C03이다. 옷장 시안에 대한 사전 답변은 착수 조건이 아니며, 단계별 화면·기능 검증은 그대로 필요하다.
- 추가 기획 없이 가능한 작업: 위 내부 정리·통합 검증·옷장 제작, 이미 범위가 정해진 음량/전체화면/화면 흔들림 설정, 언어 전환 기반과 번역 초안, 현재 규칙의 입력·화면·맵·온라인 대전 점검. 봇 난이도는 설정/선택 연결 준비까지 가능하지만 실제 수치·라운드별 적용 방식·출시값은 미정 상태로 유지한다.
- 남은 밸런스·공개 정보·맵 선택·부스 초기화 결정은 관련 기능 변경만 보류하며, 게임 규칙을 보존하는 작업 전체를 막지 않는다. 이번 갱신은 결정과 계획 확인이며 코드 구현·실행 테스트의 완료 기록이 아니다.

## 이전 범위 결정 — 2026-09-29

- 타로 카드는 구현하지 않음. 기존 지급/선택 노출 정리는 기능 개발과 분리하여 계획함.
- 봇 시작 스탯·시작 아이템 변경과 난이도 선택은 후속 BT 작업에서 진행.
- 색상 커스터마이징은 필요 없음. 스프라이트·아틀라스 교체 방식을 사용.
- 완성형 옷장은 전체 리팩토링 검증 이후 구현.
- 실행 순서·책임 분리·검증 기준: [PLAN_037](Plans/PLAN_037_gameplay_modular_refactor.md). 현재는 계획 작성 단계이며 런타임 코드는 변경하지 않음.

이 결정이 아래의 과거 보류 설명보다 우선한다. 아래의 과거 구현 설명과 집계는 현재 진행률로 사용하지 않는다.
